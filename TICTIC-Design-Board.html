Clock · overview

Live digital or analog face, greeting, ordinal date, alarm cards, timer/routine shortcuts and horizontally scrolling world clocks. Clock is the home route for alarm management.

  • Alarm cards show each upcoming date/time; toggle to enable/disable and tap to edit. Snoozed alarms remain visible with a Cancel snooze action; all alarm entries remain manageable.
  • World clocks default to Home / London / Tokyo; Add opens preset zones or custom IANA ID entry. Long-press to remove non-home zones.
  • Clock format, face, theme, accent, seconds and adaptive Battery Saver behavior live in Settings.
Live, local timeWorld zonesClock / Alarms route

Timer

Countdown screen with editable duration, live readout, start/pause/resume/reset and completion notification. The custom picker has hours, minutes and seconds with an updating preview; common durations are one-tap presets. Timer state persists locally.

  • Zero duration is rejected; selecting a new duration while running pauses before applying.
  • Widget shortcuts deep-link to Timer; timer widgets are offline and do not need weather or network access.
H · M · SPreset startLocal notification

Stopwatch

Elapsed-time screen with start/pause, lap capture and reset. Live hundredths while foregrounded; lap history and timing stay on device.

Local onlyLap actions

Routines

Schedule list for Focus block, Wind down, Morning start or Custom. Each routine has a name, time, repeat days and duration; at its scheduled time it becomes active, then clears at the chosen duration.

  • Toggle routines on/off; tap to edit; delete via editor.
  • Routine scheduling is local and OS-managed; exact delivery depends on Android settings.

Usage

Today / 7-day / 30-day local summaries, estimated app foreground and Clock-screen time, action totals, widget refresh counts, saved setup and chronological recent history.

  • Metrics and event-history saving have separate Settings switches.
  • Clear removes history; pausing history stops new events but retains existing entries.
  • Counts are not battery attribution or precise per-screen measurement.

Reminders

Dedicated destination for local one-time or weekly reminders, optional note/vibration, enable/pause, edit/delete and completion. Notification actions offer Done and 10-minute Snooze. Weekly schedules remain active after Done; one-time reminders complete.

  • Android notification permission is requested when needed; without it, reminders can be saved but alerts may be suppressed.
  • Schedules are restored after reboot, package update and system time/timezone changes. Without exact-alarm access, Android may deliver late.
  • No network is used. Reminder records and notes remain on device.

Alarm editor · dialog

Primary surface is an analogue, circular-drag time dial with clear hour/minute and AM/PM selection. Repeat is a real switch: choose local weekdays or a one-time date. Secondary label, snooze, alarm tone, vibration, gradual volume and pre-alarm options start collapsed under More settings.

  • New alarms inherit Settings → Alarms defaults; changes under More settings affect only that alarm.
  • Pre-alarm defaults to a separate short TicTic ping 30 minutes before; choose a preset or custom 1–180 minutes. A passed lead time is explained before saving.
  • Delete cancels alarm, pre-alarm and pending snooze. Exact-alarm, notification and (Android 14+) full-screen access are explained contextually.

Alarm surface · system / app

The ringing screen has large, high-contrast, labeled Snooze and Stop controls, with Turn off for repeating alarms. The notification itself carries direct Snooze and Stop actions and Turn off when repeating. Snoozed times are shown in the alarm list with a cancel action. Volume keys can be set to Control volume, Snooze or Stop while TicTic’s ringing activity is active.

Android owns the Power key; apps cannot reliably intercept it, so TicTic does not promise Power-to-snooze. Exact timing, notification delivery, full-screen launch, lock-screen visibility and audio can still be affected by permissions, channels, OEM and battery policy.

Settings · popup

Centered, scrollable panel opened from the header gear. Theme System / Light / Dark; Digital/Analog home face; System / 12 h / 24 h time format; eight accent choices; app card corner and spacing; a dedicated Alarms section for new-alarm snooze/vibration/tone/gradual-volume/pre-alarm defaults; efficiency/data controls; widget gallery; detailed Permissions & access; About and local backup export.

Widget Gallery · screen

Twenty short-named curated provider entries in two groups: five core clocks and fifteen selections from existing providers. This curation is not the separate requirement for 15 genuinely new, distinct widget concepts; that work remains outstanding. Selecting a card requests a launcher pin where supported; otherwise users can add TicTic from their launcher’s widget drawer.

System-owned surfaces & fallbacks

Android’s Alarms & reminders access page, notification prompt/settings, full-screen-intent access, notification-channel controls, ringtone picker, document-save picker and launcher confirmation are system UI. TicTic requests/opens these only from contextual flows or Settings and explains which are optional. If a picker is unavailable, it shows an error and preserves local state.

Widget behavior contract

Widgets resize across horizontal/vertical sizes. Compact dimensions hide optional rows; larger options show more content. Every placed instance has independent style settings. Tapping opens the relevant TicTic destination; Console additionally exposes two action buttons. Launcher reconfiguration, pin requests, widget padding and any lock-screen location depend on Android/OEM support.

Widget-specific settings

Clock size/typeface/alignment and panel surface stay relevant to most designs. Date formats are hidden on timer-only designs; alarm detail is hidden where no alarm row exists; optional context and label controls appear only on widgets that render those rows. Weather controls appear only on supported layouts.

Weather controls · supported widgets only

Weather toggle, manual city field and requested update interval choices of 30, 60 or 120 minutes. Values are saved per widget ID. Turning off cancels that widget’s scheduled jobs; deleting the widget removes its jobs and cached values.

Android periodic work is inexact and may wait for network constraints. The selected interval is not a guaranteed refresh time. The free Open-Meteo API is non-commercial only; commercial releases require a paid plan or a different licensed provider.

Wallpaper palette · opt-in

“Match wallpaper colors” is an explicit toggle on the configured widget. It uses only the system-exposed WallpaperColors palette. No image file access, screen capture, wallpaper picker, storage permission or runtime prompt. API/platform/null-color failures use the bundled sample palette.

Surface vocabulary

Widget default · Rounded · Square · Pill · TicTic glass · Outline only · No panel. Glass is a static translucent treatment, not a screenshot blur. Opacity control is visually grouped beside panel swatches and disabled for transparent/no-panel surfaces.

Alarms · new-item defaults

Settings → Alarms configures defaults for new alarms: snooze duration, vibration, gradual volume, alarm tone, pre-alarm enabled state, lead time, tone and vibration. Existing and new alarms can override values in More settings without changing global defaults.

Permissions & access

  • Alarms & reminders: optional to save; without it alarms/early pings can be delayed.
  • Notifications: optional to save; needed for pre-ping, reminder alerts and notification actions. Reminder channels can be silenced independently.
  • Full-screen alarm view (Android 14+): optional; affects whether the large lock-screen view launches.
  • INTERNET is used only for opted-in per-widget weather; no location/storage/screen-capture permission.
  • Vibration, foreground service, wake lock and reboot receiver are system declarations; wallpaper adaptation reads WallpaperColors metadata only.
  • Power key is not interceptable; volume handling depends on the alarm activity receiving the key.

07 / privacy boundary

What stays offline—and what doesn’t

Network and system access are intentionally narrow and directly controlled.

Offline by default

  • Clock, alarms, alarm sounds, timer, stopwatch, routines, world-clock formatting, widget layout/style, local counters/history and backup/export.
  • No account, advertising, remote analytics or third-party app runtime dependency.
  • Weather settings are off by default; each supported widget is configured independently.
  • Manual city entry avoids asking for device location. No location permission is declared.

Optional weather data path

  • Manifest INTERNET is an install-time Android permission, not a runtime location prompt.
  • Only after weather is enabled and applied for a widget, the entered city is sent to Open-Meteo’s geocoding API; coordinates are used to request current forecast data.
  • Result is cached in app-private preferences and displayed with provider attribution. Network/parse failures do not fabricate weather.
  • Free service: non-commercial only; CC BY 4.0 attribution. Commercial use requires Open-Meteo’s paid plan or another properly licensed data source.

Wallpaper color path

On supported Android releases, opted-in widgets request WallpaperColors metadata only. This is not a wallpaper image, screenshot, screen recording, broad storage access, or picker flow. When metadata is unavailable, TicTic renders its built-in sample palette. No permission prompt is presented.

08 / release notes

QA status & references

Build and device validation are different. This board records both honestly.

Build checks · v1.9.5

  • Android SDK 34 debug compile/package: PASS; APK metadata, zipalign and v1/v2 signature checks: PASS.
  • Gradle Android test task: NO-SOURCE. Python source-contract checks: 20/20 pass (static only).
  • Lint not run. A 49-case regression matrix, including dial, reminders, defaults and theme contrast, is recorded in QA-Clock-Comparison-v1.9.5.xlsx; functional cases remain NOT RUN.
  • No emulator or physical device attached. Gesture feel, scheduling precision, notification delivery, exact permission, audio, lock-screen and hardware-key behavior remain unverified.

Manual device checklist

  • Place all curated widgets at compact and expanded sizes; validate launcher padding, line breaks, contrast and tap targets.
  • Open Studio for each capability profile; check hidden irrelevant options, fixed preview during scroll, Apply vs Cancel, and edit-in-place.
  • Toggle per-widget weather; confirm network is idle while off, interval changes reschedule, network loss keeps cached data, and deleting the widget cancels jobs.
  • Verify no location or wallpaper prompt; validate WallpaperColors absence fallback.
  • Alarm QA: save with/without exact access and notifications; test early-reminder lead warning, channel disabled/silent states, reboot/time-change, screen-off/locked alarm, snooze/stop on screen and notification, turn off repeat, list/cancel snooze, and volume-key modes on each OEM/Android version. Confirm Power remains Android-controlled.
  • Then test routines, timer/stopwatch, metrics and backup.
