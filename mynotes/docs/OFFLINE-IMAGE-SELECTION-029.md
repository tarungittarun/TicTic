# Offline image selection and playback — 0.29 development work

**Qualification in progress; not yet a qualified APK recommendation.** Version 0.29.0 / code 32
keeps package `app.space.notes`, the existing sideload signer and the existing Vosk/Tesseract
model weights. No Internet permission, cloud service, account, downloader or private-data
upload is introduced into the app. Android builds and device tests run in Actions only.

## Image workflow

1. In a note/Doc, choose **Insert / Add to note → Read image**, or start Read image from Home.
   The existing automatic English + Hindi + Kannada OCR still runs without a language prompt.
2. On **Review recognized text**, tap the visible **Select from image ↗** action (or the image
   icon in the heading). The full-screen preview shows the bounded, EXIF-oriented source
   pixels, not the dark-mode-normalized pixels used internally by OCR.
3. Recognized words have blue boxes. Initially all recognized words are selected. **Clear**
   then tap individual words, or drag a rectangle. Dragging replaces the text-region selection;
   taps toggle words. Pinch to zoom up to 8×; two fingers pan; **Reset zoom** returns to fit.
4. **Choose words** offers native checkboxes as an accessible alternative to precise touching.
   Text comes from the recognizer's reading order, with line boundaries retained; it is not
   generated by an LLM. **Select all** selects all words and the full image area.
5. **Use selected text** replaces only the review field. It does not insert anything into your
   note. Existing manual changes in that field are replaced only by this explicit action.
   Review/correct the result, then use the existing **Append to note / Save as new note** action.
6. **Keep selected image** is a separate, committing action: it saves the yellow-outlined area
   as an embedded image in the original note, or a new note when launched from Home. It does
   not append the OCR text too. Text boxes are not required: an emoji, icon, diagram or object
   can be preserved as pixels without pretending to recognize its meaning.
7. Closing selection does not save a note. Back from OCR review leaves saved notes unchanged.
   The original image file is never edited or deleted.

### Honest limits and safety

This is **offline text-region selection and visual copying**, not unrestricted Google Lens
object recognition or universal emoji-to-Unicode conversion. Printed text, languages, fonts,
handwriting, low resolution, glare and decorative symbols can still be misread. Unsupported
emoji should be kept as an image or corrected manually, not assigned a guessed character.
The help text inside the selection window explains that distinction.

Local-source restrictions remain unchanged. Input copying is capped at 32 MiB; decoding is
bounded to approximately 4 MP / 2400 pixels on an edge. Preview and OCR share normalized box
coordinates even when OCR preprocessing upscales/inverts a separate bitmap. Crops are
metadata-stripped, reduced to at most 1600 pixels on an edge and encoded within existing
note/backup bounds. A visual copy is **not a bit-for-bit copy of the original full-resolution
file**. Keep your original if full resolution or metadata is important.

Region parsing is capped at 2,000,000 XHTML characters / 4096 words / 2000 characters per
word. Unsupported region markup falls back to ordinary editable full-text review rather than
silently discarding the OCR text. Text extraction is capped at 100,000 characters. Image
pixels are reference-counted while a background crop runs; cancellation, page changes and
controller closure release previews and queued results safely. OCR/preprocessing failures,
low memory, unsupported playback effects and storage rejection produce actionable messages.
No app can promise to recover from every OS kill or native process failure; existing safe-start
and local diagnostics remain available. No private source is logged or uploaded by this flow.

## Optional playback boost

The Voice inbox has **Boost quiet playback (+6 dB)**, off by default and scoped to that player.
It uses Android's session-specific `LoudnessEnhancer` when supported. Turning it off or
leaving/releasing the player releases the effect. Unsupported device effects fall back to
normal playback with a message. MediaPlayer preparation, seeking, completion and release
have additional guarded error paths.

This is gain, **not noise removal or guaranteed clearer speech**. It can amplify background
noise or distort louder passages; turn it off if that happens. It does not rewrite, normalize,
filter or replace the stored WAV, change exports, or change ASR input/model weights.
Emulator playback/lifecycle tests cannot establish Motorola speaker/microphone quality.

## Indian speech training, separate from the app

The new `notes-indian-speech-pilot.yml` workflow attempts a quarantined, genuine supervised
Whisper tiny.en **final-decoder-block** optimization on public CMU ARCTIC KSP Indian-English
read speech. Primary speaker metadata, original permissive grants and archive checksums must
pass first. The data, frozen base model and checkpoint stay outside Git and outside the APK;
only small provenance/result documents should be retained in the repository.

The pilot uses 32 KSP training utterances; 16 different SLT utterances form a speaker/text-
disjoint **US-English regression control**, not an Indian-accent benchmark. No unseen Indian
speaker is evaluated. This small experiment cannot meet the production adoption gate or
establish spontaneous dictation, Hindi/Kannada code switching, silence/noise robustness or
physical-phone latency. The experiment compares Whisper before/after, not production Vosk
against an accepted replacement. Report actual optimizer steps, modified parameters, hashes,
losses, hypotheses and WER; failed preflight or downloads are **not training**.

Until a completed optimization report is available, training remains **unproven**. Even with
one, the app's existing working speech engine stays unchanged until representative Indian
speaker-held-out and Android/physical qualification passes. See
`INDIAN-SPEECH-ADAPTATION-PROTOCOL.md` for the broader acceptance requirements.

## Physical acceptance checklist

- Install only a subsequently qualified 0.29 APK **over** the existing app. Do not uninstall,
  clear data, downgrade, or delete the App folder as a test on your sole real library.
- Keep an independent verified backup first; confirm existing Notes, Docs, images, drawings,
  folders, labels, pins, voice files and history still open after upgrading/restarting.
- In airplane mode, scan a real English/Hindi/Kannada page and a mixed photo; clear/select
  specific regions, zoom/pan, use the word list, correct text and append/save a new note.
- Cancel at processing/review/selection stages; verify the original note and source photo.
- Keep an emoji/object as an image crop, then reopen/export/restore it; distinguish that visual
  preservation from interpreting the object or producing an emoji character.
- Test font size, landscape, TalkBack and keyboard reachability. Verify word boxes align with
  source pixels, including rotated and dark screenshots. Check that errors remain understandable.
- Play the same quiet recording at a fixed system volume with boost off/on/off. Listen on the
  Motorola speaker, headphones and another device. Note distortion/noise, routes and whether
  the effect is supported. Exported original WAV bytes must remain unchanged.
- Do not report automation as physical acceptance or a tiny training pilot as Indian-ASR
  completion. Report exact remaining failures and preserve a diagnostic trace for real crashes.
